# 好友文字聊天

日期：2026-10-28。基于现有互关好友、Cookie 会话与云 MySQL，新增一对一文字私聊。

## 使用

- 从左侧“好友聊天”、顶部聊天图标或用户菜单进入 [聊天页面](http://127.0.0.1:5173/messages)。
- 在互关好友列表或好友个人主页点击“发消息”，可以开启新对话。
- 支持会话搜索、会话分页、历史消息分页、未读数量和已读回执；Enter 发送，Shift + Enter 换行。
- 新消息即时提示并增量读取。向上查看旧消息时保留阅读位置，新消息通过按钮提示跳转。
- 发送中、发送失败和重试均有实际状态；失败重试使用原发送标识，避免重复保存。
- 手机宽度下在会话列表与当前对话之间切换，提供返回入口。

只有双方账号正常且互相关注时才能发送新消息。解除互关或对方停用后，双方已有历史仍可查看，输入区域改为只读提示；恢复互关后可以继续交流。其他用户及管理员不能通过更改用户 ID 查看不属于自己的私聊。

消息以纯文本显示，最多 2000 个 UTF-16 字符；HTML 字符不会当作页面标签执行。本轮没有图片、文件、语音、群聊或消息撤回入口。

已保存消息从云数据库读取，刷新和重启后保留。未发草稿及发送失败队列仅保存在当前页面内存中，完整刷新页面后不恢复；需要保留时先重试或复制文本。

## 后端与数据

新增 `server/migrations/007_direct_messages.sql`：

- `dm_conversations`：双方规范用户 ID 的唯一会话、最近一条消息索引、时间。
- `dm_messages`：正文、发送方、接收方、发送标识、时间和已读时间；包含会话／消息游标、接收方未读、发送频率索引。
- `sender_id + client_id` 唯一；事务锁定双方用户，校验互关与账号状态。相同请求重试返回原消息，替换正文或接收方返回 409。
- 每人每分钟最多 30 条新消息，已成功消息的幂等重试不占新额度。
- 消息 BIGINT 编号通过字符串传输，前端精确比较，避免超过 JavaScript 安全整数后丢失顺序。

| 接口                                              | 行为                                                   |
| ------------------------------------------------- | ------------------------------------------------------ |
| `GET /api/chat/unread`                            | 当前账号私聊未读总数                                   |
| `GET /api/chat/threads?page=1&pageSize=20&q=`     | 当前账号会话列表、分页和搜索                           |
| `GET /api/chat/threads/:peerId/messages?limit=30` | 最新消息与双方关系、已读游标                           |
| 同接口 `before=` 或 `after=`                      | 更早历史或新消息增量，最多 50 条，不能同时指定两个方向 |
| `POST /api/chat/threads/:peerId/messages`         | `{content, clientId}` 发送消息                         |
| `PUT /api/chat/threads/:peerId/read`              | `{upToId}` 标记当前会话的接收消息为已读                |
| `GET /api/chat/events`                            | 已认证 SSE 变更提示                                    |

所有接口校验当前登录身份，写接口另校验 Origin 和 CSRF。已读游标必须属于当前会话，不得标记其他对话。私聊内容不进入公共 bootstrap、公共用户列表或通用社区通知正文，响应为 `private, no-store`。

## 实时更新与资源

服务器仅通过 SSE 发送 `ready/change` 与空对象提示；正文、未读数和已读游标经有权限的接口读取。25 秒验证连接对应的会话并发送心跳；关闭连接时清理计时器。服务退出前主动关闭长连接，避免正常停止一直等待。

浏览器隐藏时暂停连接，恢复时补读；断线自动重连，失效时使用 30 秒间隔补读。当前对话有新消息时增量读取，关注或聊天操作不会重新下载整包社区数据。无需新增 Redis 或 WebSocket 依赖。

当前事件分发针对单个应用进程。未来使用多实例时需增加共享事件层。每账号 4 条、全局 100 条连接是程序保护上限，不代表已验证的服务器并发承载能力。

## 启动与部署

现有环境先运行 `npm run db:migrate`，再执行 `npm start`；新环境按原部署文档配置数据库并执行 `npm run db:init`。

反向代理 `/api/chat/events` 时关闭缓存和响应缓冲，保留 Cookie 与 Origin，使用 HTTP/1.1，读取等待时间应大于 25 秒心跳间隔。生产环境仍需 HTTPS 与合规的数据库加密连接，不能通过关闭保护来部署。
