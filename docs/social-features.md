# 关注、粉丝与互关好友

日期：2026-10-28。沿用现有 LearnHub 页面、账号体系和云 MySQL，为已有作者主页、论坛、问答和消息入口补充真实关系功能。

## 使用方式

- 在用户主页、帖子详情作者信息及侧栏、问题提问者旁点击关注；对方已经关注自己时显示“回关”。
- 双方互相关注即为好友；任一方取消关注后解除好友关系，不单独维护易失配的好友表。
- 点击个人主页上的关注数、粉丝数进入分页列表；左侧“关注与好友”和用户菜单也可进入。列表支持昵称、简介搜索，以及回关、取消关注。
- 自己可以查看好友列表；他人的关注、粉丝列表公开，好友列表仅本人可见。关系数量均由数据库计算，停用账号不进入数量、列表和关注动态。
- 论坛新增“发现讨论／关注动态”，关注动态从数据库读取已关注作者的公开帖子，支持原有分类、关键词、排序和分页。登录后可查看。
- 新粉丝通知进入原消息中心，可标为已读、删除或跳转关注者主页。同一方向的首次关注只发一次通知；取消再关注、重复请求、删除旧通知后重试均不会刷出新通知。关注不奖励积分。

数据没有写入 localStorage；页面状态保存在内存中，刷新和重启服务后从云数据库重读。好友申请、私信和分组不属于本轮范围。

## 数据与接口

新增迁移：`server/migrations/006_social_follows.sql`。

- `user_follows`：`follower_id + followee_id` 唯一主键，双向时间索引、用户外键级联、自关注 CHECK。
- `follow_notification_events`：保留首次关注事件，关系取消或通知删除后仍能防止重复通知，账号删除时级联清理。

| 接口                                                                                       | 行为                                                     |
| ------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| `GET /api/members/:id/social`                                                              | 关注数、粉丝数、好友数及访问者相对关系                   |
| `PUT /api/members/:id/follow`                                                              | `{ "active": true/false }` 关注开关；需登录及 CSRF       |
| `GET /api/members/:id/connections?type=following\|followers\|friends&page=1&pageSize=8&q=` | 关系名单、总数与分页，好友名单校验本人                   |
| `GET /api/posts?scope=following`                                                           | 已关注作者的公开帖子，需登录，沿用分类、搜索、排序、分页 |

写入事务使用数据库规范用户 ID，按固定顺序锁定双方用户，锁定后再次检查账号状态。避免自己 ID 大小写变体绕过校验、互关锁序冲突和并发重复记录。所有统计、关系名单及动态来自真实表，返回公开用户字段，不泄露邮箱或密码。

前端 `src/stores/social.ts` 合并同一作者的状态读取，列表直接携带每位用户的关系，避免逐用户单独请求。关注成功采用服务端返回值，仅刷新必要的关系统计，不重新下载全量 bootstrap。按登录用户隔离状态并忽略切换账号前的旧响应。

## 启动与复测

现有项目升级时先运行 `npm run db:migrate`，再运行 `npm start`；新环境仍按原部署说明配置数据库并执行 `npm run db:init`。迁移不重置已有用户或内容，本轮已再次运行确认不会重复应用。

打开 [关注与好友](http://127.0.0.1:5173/connections)、[关注动态](http://127.0.0.1:5173/forum?scope=following) 或任意用户主页体验。未登录时页面提供登录入口；受保护接口仍在服务端拒绝游客。
